## 结论概览

在这批 repo 里，**两个站点的"音乐种子字段"来源并不对等**：

| 站点 | 出现的仓库 | 是否有音乐专用字段定义 |
|---|---|---|
| **憨憨 hhanclub / hhanclub.net / hhanclub.top** | `easy-upload`（HH.yaml + hanhan.ts 专用 extractor）、`PT-Plugin-Plus`（hhanclub.top/config.json）、`auto_feed_js`（转发端 `HHClub`） | ❌ 三个仓库都**没有**独立"音乐"字段；easy-upload 只按通用影视字段抓取，音乐类不在其支持范围内 |
| **蟹黄宝 crabpt.vip** | **仅** `auto_feed_js/auto_feed.user.js` | ❌ 代码里只有"音乐"作为分类值(type=408)，**没有** music_type / tracklist 等音乐专用字段的填充逻辑 |

⚠️ 注意：`easy-upload/src/config/Carpt.yaml` 是 **carpt.net**（与 crabpt.vip 无关），别搞混。

## 关键提示（容易看错的地方）

1. **crabpt.vip ≠ carpt.net**。`easy-upload/src/config/Carpt.yaml`（`carpt.net`，有 movie/tv/music=406 等完整上传映射）是**蟹黄宝以外的另一个站**，不要拿它的字段当 crabpt.vip 的答案。
2. **两个站在现有仓库里都没有"音乐种子专属字段集"**——音乐只是 `type/category` 的一个取值（憨憨侧由 `getCategoryFromSource` 归并，蟹黄宝侧为 `browsecat=408`）。真正的音乐专属字段（`tracklist`、`music_type`、`music_media`、`log_info` 等）只存在于 `auto_feed_js` 里针对 **RED / OPS / DICMusic / SugoiMusic** 等音乐站的抓取分支。
3. 若你要做的是"音乐种子的**上传表单**字段"，憨憨目前**不支持作为上传目标**（`asTarget: false`），蟹黄宝的上传字段以表二第 2 节为准。
