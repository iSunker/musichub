# 文档投影 · 用法与基线

**建于 2026-09-14**（`tools/doc-audit/`）。基线快照：`out.baseline-20260914/`。

> ★ 这份文档**不是第四份事实源**。
> 它只说两件事：**这些投影怎么用**，以及**某一天量到的读数是多少**。
> 环境事实仍然只在 `README` / `SUMMARY` / `ENVIRONMENT` 三处维护；
> 这里的数字是**一次测量的快照**，会过期，**过期了以重跑为准**。

---

## 一、这是什么

三份大文档（`README` / `SUMMARY` / `ENVIRONMENT`）是**唯一事实源**。它们太大，检索靠人眼。
`tools/doc-audit/` 干的事不是拆文档，是**给它们做投影**：

```
        ┌─ 事实源（唯一）──────────────────────────┐
        │  README.md   SUMMARY.md   ENVIRONMENT.md │
        └───────────────────┬──────────────────────┘
                            │  只读，可反复跑
        ┌───────────────────┴──────────────────────┐
        │  01_headings  → out/headings.tsv   结构树 │
        │  02_refs      → out/refs.tsv       引用表 │
        │  03_terms     → out/terms.tsv      倒排表 │
        │  04_probes    → out/probes.tsv     事实表 │
        └──────────────────────────────────────────┘
```

**投影只读事实源，事实源不读投影。** 这条方向不能反过来 —— 一旦反了就成了环，两边都会漂。

`out/` 与 `out.baseline-*/` 都在 `.gitignore` 里，但**理由不同**：
`out/` 是**可反复生成的派生数据**，冻进仓库只会变成一条会漂的"事实"；
`out.baseline-*/` 是**一次测量的快照**，进 git 就会从"某天的读数"升级成"事实源"。
两种都不该进。

## 二、四份投影各自什么时候用

| 脚本 | 产出 | 什么时候用 | 判据（健康长什么样） |
|---|---|---|---|
| `01_headings.py` | `out/headings.tsv`<br>file / level / line / slug / title / parent | ① 加章加节后看层级有没有跳<br>② 想知道某节在哪一层 | **0 个层级跳跃**；**0 处围栏缺陷** |
| `02_refs.py` | `out/refs.tsv`<br>src / line / ref / status / target / hint | ★ **改完任何标题、或挪动任何章节之后必跑** | **悬空 0**、半悬空 0、锚点无命中 0、锚点歧义 0 |
| `03_terms.py` | `out/terms.tsv`<br>term / file / line / context | 找「同一事实散在多处」的嫌疑；或某个常量改名前先看它散在哪 | 跨 ≥2 文件的关键词**逐个有人认领**（认领 = 该留的留、该并的并） |
| `04_probes.py` | `out/probes.tsv`<br>probe / actual / error | 怀疑文档里某个数字过时了；或想确认生产真是那样 | 每个数字能与文档声称逐条对上；`error` 列为空的探针越多越好 |

跑法（站在**仓库根**，不用带参数；`DOCS` 默认就是本仓库）：

```bash
python tools/doc-audit/01_headings.py
python tools/doc-audit/02_refs.py
python tools/doc-audit/03_terms.py
python tools/doc-audit/04_probes.py     # ★ 这条走 SMB 读 NAS，最慢
```

### `02_refs.py` 管的五族锚点

改标题之前先知道哪些东西挂在标题上：

| 族 | 形态 | 目标在哪 |
|---|---|---|
| ① | `§N` / `§N.M` / `§N.M.K` | SUMMARY 的编号标题（`## 6.` / `### 3.16` 都认）|
| ② | `ERR-XX-NN` | `ENVIRONMENT.md` 的 H3 条目 |
| ③ | `README「…」` / `ENVIRONMENT「…」` | 对应文档的标题（**子串命中且必须唯一**）|
| ④ | `A.N` / `B.N` | `ENVIRONMENT.md` 自己的 H2 |
| ⑤ | 围栏内的引用 | **不算** —— 代码示例里的 `§N` 是示例，不是引用 |

★ **只有五族，比姊妹项目少一族。** 那边还有「`弯路 #N`」——本项目**没有**：
`走过的弯路.md` 并入 **SUMMARY §6** 时就删了，全仓库**没有任何该形状的引用**。
少一族就少一类假警报；代价是若将来真写出 `弯路 #N`，它会**静默漏检** —— 这是刻意选的。

### ★ 为什么走围栏要按 CommonMark，不能"见到 ``` 就翻"

「见到 ``` 就翻」的写法会在「**行尾**三反引号」（形如 ``**已沉淀成工具**：``` ``）那一行永久失步 ——
CommonMark 说那是**内联代码**，不是围栏；而它会把**下一行的裸 ``` 一起吃掉**。

⇒ 一家伙错位，后面 100+ 个真标题会被当成代码块内容吞掉（姊妹项目实测）。
所以走行逻辑抽在 **`mdwalk.py`** 里，四份脚本共用 —— **不做四份会各自漂的拷贝**。
它还会在收尾时**报围栏缺陷**，而不是闷头算错。

## 六、安全纪律（改这些脚本时**必须守住**）

**两条都要有，缺一条就是漏洞：**

1. **只打聚合。** 判「库里有多少条、回填了多少」**只需要计数** ——
   行内容（`torrent_name` / `cover_url` / `tracklist`）对判读**零价值**，**一律不取**。能不取就不取。
2. **出口统一过 `redact()`。** 万一某个探针必须碰这类列、或异常信息里带出来，
   在**打印和落盘之前**按**值的形状**抹掉。按**键名**匹配会漏掉嵌在异常文本里的凭据 ⇒ 兜底要按形状。

★ 本项目还有一条**额外的**：**本机 `.env` 是真凭据副本**（`ENVIRONMENT.md` A.5）。
所以探针**全程不读任何配置文件**，要用的地址是写死的公开端点。
> 判据是「**只读 + 不回显凭据 + 只打聚合**」这三条同时成立。

另外：**探针一律只读**。库用 `query_only`，**UNC 直读、不 `cp` 副本**（WAL 里未 checkpoint 的数据会丢，见 `ERR-SQL-01`）。

## 七、审计过程**自己**的纪律

> 前面六节讲的是被审文档的坑。这一节讲**"审计动作"本身** —— 因为判据自己也要先被验证一次。

### ★ hash 变了 **≠** 结构变了 —— 三份表**都嵌了行号**

| 表 | 列 |
|---|---|
| `headings.tsv` | file / level / **line** / slug / title / parent |
| `refs.tsv` | src / **line** / ref / status / target / hint |
| `terms.tsv` | term / file / **line** / context |
| `probes.tsv` | probe / actual / error（**不嵌行号**，但读数**随时间**变）|

⇒ **任何插入 —— 哪怕只加一行正文、标题与关键词一个都没动 —— 都会让前三份的 hash 同时变。**
**而三份全红可能是三个不同的原因**（有的只是行号列在动，有的是引用真变了），**光看 hash 分不出哪个是哪个。**

**所以比对必须分两层**：先 `sha256sum -c` 粗筛，再比 **`CONTENT.sha256`**（剔掉行号列，**这才是判据**）。
`cut` 掉行号再 diff **是事后补救**（方向对，但绕）；直接比 `CONTENT.sha256` 才对。

> ⚠ 这与 `probes.tsv` 那条**处置像、理由不同**，**别写成同一条**：
> `probes.tsv` 的第 4 列（读数）**本身就是会动的量**，**压根不该进判据**；
> 三份投影的**行号列是元数据**，内容变没变跟它无关。

### ★ 冻结是「当天最后一个动作」

**坑**：快照冻在「落定之前」—— 当天的文档改动还没做完就把 `out/` 拷成了快照。
**它为什么危险**：基线一旦冻错，**后续所有比对都是在错的参照系上做的，而比对结果看起来完全正常** ——
「变了 3 处」的真实含义可能是「**基线错了一处 + 今天正常变了两处**」，这两件事**在输出上分不开**。

**规矩**：任何「冻结快照」之前，先问一句 —— **被冻的东西，还是不是最终态？**

**判据**：冻完**立刻再跑一遍**投影，比对两次的 hash：
```bash
sha256sum out/headings.tsv out/refs.tsv out/terms.tsv
```
**相同 ⇒ 落定了。不同 ⇒ 还有东西在改文档**（或哪个脚本有不确定输出）—— **先查清再冻**。
★ **`probes.tsv` 必须排除在这条自检之外** —— 它天然每次都不同，对它用不了"两次相同"。
不排除，这条自检就**每次都报警** —— 而**一个会误报的哨兵，两次之后就没人看了**。

### ★ 拿旧版对照时，**回读你实际拿到了什么**

想用 `git show HEAD:<file>` 取「改动前的版本」时，**别忘了 HEAD 可能已经包含那次改动** ——
那样比的是「新版 vs 新版」，结论会是一个**看起来很干净的假一致**。
```bash
git show <rev>:ENVIRONMENT.md | grep -n '<这次改动的特征串>'
# 命中了 ⇒ 你拿的**不是**旧版，换个 rev
```

### ★ 空转的提交 / 推送：一个「返回 1 被我丢了」，一个「返回 0 骗了我」

| 命令 | 空转时返回 | 输出 | 谁在骗人 |
|---|---|---|---|
| `git commit`（暂存区空） | **1** | `nothing to commit, working tree clean` | **没骗人** —— 是我**没接 `&&`、也没读它** |
| `git push`（已在最新） | **0** | `Everything up-to-date` | ★ **真的会骗人** —— 0 是"成功"，事实是**什么都没推** |

**两条护栏**：
```bash
git diff --cached --quiet && { echo "★ 暂存区为空，别 commit"; exit 1; }   # commit 前
git rev-parse HEAD origin/main                                            # push 后：必须相等
```
★ **第二条是关键**：`commit` 的失败还能靠 `&&` 串出来，**`push` 的失败串不出来 —— 它返回 0**。
本项目是**直推 main**，所以推完**必须读一次真实状态**。
